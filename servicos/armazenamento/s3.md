# Amazon S3 (Simple Storage Service)

<!-- didatico:inicio -->
## 🧠 Comece pelo problema

**Qual é a dificuldade?** Uma aplicação precisa guardar fotos, documentos e outros arquivos sem administrar o disco de uma máquina específica.

**Como este serviço ajuda?** O S3 guarda dados como objetos: conteúdo, nome de identificação e informações associadas. Você organiza esses objetos em buckets e controla quem pode enviar ou ler cada um.

**Exemplo do dia a dia:** Uma escola guarda materiais em PDF no S3. Seu sistema autoriza o acesso, e os alunos baixam os documentos permitidos.

**O que ele não resolve sozinho?** S3 não executa o programa do seu site nem funciona como um disco comum instalado dentro de uma máquina. Guardar um arquivo também não significa torná-lo público.

**Primeiras palavras para entender:**

- **Objeto:** dado guardado no S3.
- **Bucket:** recipiente que organiza objetos.
- **Chave:** nome que identifica o objeto dentro do bucket.

*O exemplo é ilustrativo. Para estudar para a prova, confira o escopo indicado abaixo; para usar o serviço, confira também as condições e a documentação oficial desta ficha.*

## 1. A sequência de funcionamento

**Antes de ler este trecho:**

- **bucket:** Recipiente que organiza objetos no S3. A aplicação usa o bucket e a identificação do objeto para pedir operações autorizadas.
- **objeto:** Unidade de dados guardada no armazenamento de objetos: conteúdo, identificação e informações associadas. Não é uma máquina nem um programa em execução.
- **chave:** Pode indicar identificação de um registro, identificação de um objeto ou elemento criptográfico. Leia o contexto: localizar um dado e protegê-lo são tarefas diferentes.


**Passo 1.** Crie um bucket para organizar objetos e defina quem pode enviar e ler dados.

**Passo 2.** Envie um objeto com uma chave que o identifique. A aplicação faz operações autorizadas para gravar, obter ou excluir conteúdo.

**Passo 3.** Escolha proteção, conservação e classe de armazenamento. Apagar um objeto, guardar uma versão e manter um arquivo são decisões distintas.

## 2. Recursos e opções, com significado

### Para que serve

**Antes de ler este trecho:**

- **backup:** Cópia de segurança para recuperação. Ter uma cópia não mantém, por si só, a aplicação funcionando durante um incidente.
- **build:** Processo de preparar uma versão executável da aplicação. Pode compilar, empacotar e executar tarefas configuradas, mas não inventa os testes necessários.


Data lakes, backup e arquivamento, mídia, logs, artefatos de build.

**Antes de ler este trecho:**

- **CloudFront:** CloudFront distribui conteúdo por uma rede de pontos de presença.
- **site estático:** Conteúdo entregue como arquivos, sem executar ali toda uma aplicação de processamento de negócio. Pode integrar-se a outros serviços para funções adicionais.


**Hospedagem de site estático** (com CloudFront na frente).

**Antes de ler este trecho:**

- **CloudTrail:** Registro de atividades e chamadas AWS compatíveis. Ajuda a analisar quem realizou uma operação, em vez de medir sozinho a velocidade da aplicação.
- **Config:** Serviço que acompanha configurações e suas avaliações em recursos compatíveis. Observar configuração é diferente de observar uma métrica de desempenho.
- **origem:** Local de onde uma distribuição obtém conteúdo, como um servidor ou bucket. Uma cópia em cache não elimina toda necessidade de acessar a origem.
- **CUR:** Relatório de custos e uso. Ele ajuda a analisar consumo registrado; é diferente de uma estimativa antes de criar recursos.


Origem de conteúdo para CloudFront; destino de CloudTrail, Config, Flow Logs, CUR.

### Conceitos e componentes

**Bucket**

**Antes de ler este trecho:**

- **região:** Área geográfica AWS que contém zonas de disponibilidade. Muitos recursos são criados numa região específica; mudar de região pode exigir criar ou copiar recursos.


**O que é:** Contêiner de objetos. Nome **único globalmente**, mas o bucket fica em **uma região**.

**Objeto**

**Antes de ler este trecho:**

- **metadados:** Informações que descrevem outros dados, como características de um objeto. Conhecer a descrição não significa ler todo o conteúdo.


**O que é:** Dados + metadados + chave (o "caminho", ex.: `fotos/2026/a.jpg`). Não há pastas reais, só prefixos.

**Classe de armazenamento**

**Antes de ler este trecho:**

- **S3:** O S3 guarda dados como objetos: conteúdo, nome de identificação e informações associadas.


**O que é:** Definida por objeto. Ver [classes do S3](s3-classes-de-armazenamento.md).

**Consistência**

**Antes de ler este trecho:**

- **consistência:** Garantia sobre o que leituras observam após gravações. Não é o mesmo que durabilidade, nem garante que o dado inserido pelo programa está correto.


**O que é:** **Forte (read-after-write)** para todas as operações.

**Tipos de bucket**


**O que é:** *General purpose* (padrão), *directory buckets* (S3 Express One Zone), *table buckets* (S3 Tables/Iceberg) e *vector buckets* (S3 Vectors) — os dois últimos 🧊 fora da prova.

### Configurações e opções importantes

#### Segurança e acesso


**Block Public Access**


**Detalhe:** 4 configurações; **ativado por padrão** em buckets novos (desde 2023 ✔️) e pode ser imposto na conta toda. Para liberar acesso público é preciso a permissão `s3:PutBucketPublicAccessBlock`.

**Bucket policy**

**Antes de ler este trecho:**

- **recurso:** Algo criado ou administrado num serviço, como uma máquina, um bucket ou uma tabela. Criar um recurso não é o mesmo que contratar toda uma aplicação pronta.
- **JSON:** Formatos de dados com estruturas diferentes. O formato influencia como uma ferramenta lê e processa os arquivos; não muda sozinho o significado dos registros.
- **policy / política:** Documento ou regra que define permissões, limites ou comportamento. O contexto identifica se é uma política de identidade, de recurso ou de outra função.


**Detalhe:** Política baseada em recurso (JSON): quem pode fazer o quê no bucket (inclusive outras contas).

**IAM policies**

**Antes de ler este trecho:**

- **IAM:** Serviço para identidades e permissões de recursos AWS. Ele responde quais ações uma identidade pode fazer, conforme políticas e demais controles aplicáveis.


**Detalhe:** Permissões das identidades da conta.

**ACLs**

**Antes de ler este trecho:**

- **legado:** Sistema existente com tecnologias ou dependências que precisam ser preservadas ou avaliadas numa mudança. Antigo não significa automaticamente que pode ser desligado.


**Detalhe:** Legado. **Object Ownership = "Bucket owner enforced"** (ACLs desativadas) é o padrão.

**Presigned URL**

**Antes de ler este trecho:**

- **URL:** Endereço usado para acessar um recurso. Uma URL pode incluir domínio, caminho e parâmetros; possuir o endereço não significa ter autorização.
- **credenciais:** Informações usadas para comprovar ou representar uma identidade. Credenciais temporárias expiram; credenciais de longa duração precisam de proteção e administração.


**Detalhe:** Acesso **temporário** a um objeto privado (download/upload), assinado com credenciais de quem gerou.

**Access Points**


**Detalhe:** Pontos de acesso com políticas próprias para cada aplicação/time.

**VPC gateway endpoint**

**Antes de ler este trecho:**

- **VPC:** A VPC é uma rede virtual isolada logicamente para seus recursos.
- **endpoint:** Ponto de acesso a um serviço ou componente. Pode ser um endereço de API ou um recurso de conectividade; identifique qual sentido a seção usa.


**Detalhe:** Acesso privado ao S3 a partir da VPC, gratuito.

**OAC (CloudFront)**

**Antes de ler este trecho:**

- **OAC:** Controle de acesso à origem em integrações CloudFront compatíveis. Ajuda a restringir acesso direto à origem conforme a configuração.


**Detalhe:** Bucket privado servido só via CloudFront.


#### Criptografia


**SSE-S3**

**Antes de ler este trecho:**

- **AES-256:** Algoritmo de criptografia com chave de 256 bits. Esse nome descreve a tecnologia de proteção; autorização e administração das chaves continuam necessárias.
- **SSE-S3:** Formas de criptografia no servidor do S3, que diferem na origem e administração das chaves e, no último caso, nas camadas. A tabela da seção distingue essas escolhas.


**Chave:** Gerenciada pelo S3 (AES-256)

**Observação:** **Padrão para todo objeto novo** desde 05/01/2023 ✔️

**SSE-KMS**

**Antes de ler este trecho:**

- **KMS:** Serviço AWS para gerenciar chaves e operações criptográficas. Ter uma chave não ativa automaticamente criptografia em todos os recursos.


**Chave:** Chave do KMS

**Observação:** Auditoria no CloudTrail, controle por key policy; *S3 Bucket Keys* reduzem custo de chamadas ao KMS

**DSSE-KMS**


**Chave:** KMS, duas camadas

**Observação:** Exigências regulatórias específicas

**SSE-C**

**Antes de ler este trecho:**

- **AWS:** Amazon Web Services: provedor dos serviços de nuvem estudados aqui. Uma conta pode criar recursos e recebe cobrança conforme os serviços utilizados.


**Chave:** Fornecida pelo cliente a cada requisição

**Observação:** A AWS não guarda a chave

**Client-side**

**Antes de ler este trecho:**

- **client-side:** Ação realizada no lado do cliente. Em criptografia, significa proteger os dados antes de enviá-los ao serviço; o cliente precisa administrar sua parte do processo.


**Chave:** Cliente criptografa antes de enviar


**Antes de ler este trecho:**

- **HTTPS / TLS:** HTTPS usa TLS para proteger a conexão web. TLS é a tecnologia atual de proteção; SSL aparece como nome histórico. Essa proteção do caminho é diferente de criptografar dados armazenados.


Em trânsito: HTTPS (TLS). É possível exigir TLS com condição `aws:SecureTransport` na bucket policy.


#### Proteção de dados


**Versionamento**


**Detalhe:** Estados: desativado → **ativado** → **suspenso** (nunca volta a "desativado"). Exclusão vira *delete marker*.

**MFA Delete**

**Antes de ler este trecho:**

- **API:** Interface pela qual um programa pede uma operação a outro sistema. Por exemplo, pedir ao S3 que guarde um arquivo é uma chamada de API.
- **CLI:** SDK fornece bibliotecas para programas chamarem APIs; CLI fornece comandos de texto. As duas formas continuam exigindo identidade, autorização e configuração.
- **MFA:** Verificação adicional de autenticação, além da primeira credencial. Ela protege a entrada, mas não concede permissões por si só.
- **root:** Na conta AWS, é a identidade principal com poderes especiais. Dentro de Linux, root é o administrador do sistema operacional. Administrar Linux não é o mesmo que administrar a conta AWS.


**Detalhe:** Exige MFA para apagar versões ou mudar o versionamento; **só o root** ativa (via CLI/API).

**Object Lock**

**Antes de ler este trecho:**

- **retenção:** Tempo durante o qual dados ou registros são conservados. Depois desse prazo, o comportamento depende das regras do serviço e das configurações.
- **WORM:** Escrever uma vez e ler muitas vezes: modelo de retenção que impede alterações ou exclusões conforme o mecanismo e o modo aplicáveis.
- **compliance:** Atendimento a requisitos definidos. Usar um serviço com certificações não torna automaticamente a aplicação do cliente conforme.


**Detalhe:** **WORM**. Modos **Governance** (usuários com permissão especial podem remover) e **Compliance** (ninguém, nem o root, apaga até o fim da retenção) + **Legal hold**. Exige versionamento.

**Replicação**

**Antes de ler este trecho:**

- **Batch:** O AWS Batch organiza trabalhos em filas e fornece capacidade de computação para executá-los conforme as configurações.
- **replicação:** Manutenção de uma cópia dos dados em outro recurso. Se uma alteração incorreta for replicada, a cópia também pode recebê-la; replicação não substitui todo backup.
- **CRR / SRR:** Replicação S3 entre regiões ou na mesma região. Requisitos, objetos abrangidos e permissões precisam ser atendidos.
- **S3 RTC:** Controle de tempo de replicação do S3 com condições específicas. Não é a mesma medida que durabilidade ou tempo de recuperação de um arquivo de archive.


**Detalhe:** **CRR** (entre regiões) e **SRR** (mesma região); exige versionamento nos dois buckets; **S3 RTC** garante 99,99% em 15 min. Não replica objetos já existentes (use Batch Replication).

**Lifecycle**


**Detalhe:** Regras de **transição** (mudar de classe após X dias) e **expiração** (apagar objetos/versões antigas, multipart incompletos).


#### Performance e transferência


**Multipart upload**

**Antes de ler este trecho:**

- **GB / MB / TB:** Unidades de quantidade de dados em escala decimal: kilobyte, megabyte, gigabyte, terabyte e petabyte. Quando uma tabela fala em GB armazenados, mede volume; GB por segundo mede transferência.
- **PUT:** Nomes comuns de operações: enviar ou gravar, obter e excluir. O significado preciso e as permissões dependem da API usada.


**Detalhe:** Recomendado acima de 100 MB, **obrigatório acima de 5 GB** (PUT único vai até 5 GB); partes de 5 MB até objetos de 50 TB. Upload pelo console: até 160 GB.

**Transfer Acceleration**


**Detalhe:** Upload via edge locations do CloudFront para longas distâncias.

**Byte-range fetches**


**Detalhe:** Download paralelo de partes de um objeto.

**Requester Pays**


**Detalhe:** Quem baixa paga a transferência e as requisições.


#### Outros recursos


**Antes de ler este trecho:**

- **Lambda:** No Lambda, você entrega uma função, isto é, um trecho de programa.
- **SQS:** SQS guarda mensagens numa fila até que consumidores as recebam e processem.
- **SNS:** SNS publica mensagens em tópicos e as distribui a assinantes compatíveis.
- **EventBridge:** EventBridge recebe eventos e usa regras para encaminhá-los a destinos compatíveis.


**Event notifications** → Lambda, SQS, SNS ou EventBridge.

**Antes de ler este trecho:**

- **HTTP:** Protocolo de pedidos e respostas usado na web. Uma URL e um método indicam a operação; HTTP sozinho não protege o conteúdo por criptografia.


**Static website hosting**: endpoint HTTP do site; documento index e de erro.

**Antes de ler este trecho:**

- **CORS:** Regras de acesso entre origens usadas pelo navegador. Permitir uma origem não substitui a autenticação e a autorização do recurso.


**CORS**, **S3 Inventory**, **Storage Lens** (painel de uso e custo), **Batch Operations**, **S3 Select** (legado), **Object Lambda**.


**Server access logs** e CloudTrail *data events* para auditoria de leituras/escritas.

### Limites e números

**Antes de ler este trecho:**

- **durabilidade:** Capacidade de preservar os dados armazenados. É diferente de disponibilidade, que trata de conseguir acessá-los quando necessário.


📌 Durabilidade **99,999999999% (11 noves)** em todas as classes.


📌 Objeto máximo: 🔄 **50 TB** desde 02/12/2025 (antes **5 TB**; não vale no GovCloud). Distinga o tamanho do objeto do limite por método de upload.


📌 PUT único até 5 GB; multipart obrigatório acima disso.

**Antes de ler este trecho:**

- **segundo:** Unidades de tempo. Em cobrança, tempo de recurso provisionado pode importar mesmo sem usuários acessando; em recuperação, tempo representa a espera para voltar a usar algo.


🧊 Até 1 milhão de buckets por conta (antes 100 padrão); 3.500 PUT e 5.500 GET por segundo por prefixo.

## 3. Como escolher e reconhecer os limites

Uma opção deve atender ao requisito da aplicação. Compare função, compatibilidade, responsabilidade e condições; preço ou uma palavra do enunciado não bastam isoladamente.

S3 não executa o programa do seu site nem funciona como um disco comum instalado dentro de uma máquina. Guardar um arquivo também não significa torná-lo público.

### ⚠️ Pegadinhas e não confundir

**Antes de ler este trecho:**

- **regional:** O recurso ou a operação pertence a uma região. Serviços globais podem administrar objetos regionais; leia o alcance do recurso, não apenas o nome do serviço.
- **global:** Alcance que não se limita ao gerenciamento de uma única região. Isso não significa que cada dado foi automaticamente copiado para todo o mundo.


S3 é **regional**; só o *namespace* de nomes é global.


**Versionamento** protege contra exclusão acidental; **Object Lock** garante imutabilidade (WORM); **MFA Delete** exige MFA.


**Presigned URL** (S3) × **signed URL** (CloudFront).

**Antes de ler este trecho:**

- **EBS:** O EBS fornece volumes, isto é, discos virtuais que podem ser conectados a máquinas EC2 compatíveis.
- **EFS:** O EFS oferece um sistema de arquivos compartilhado.
- **instância:** Máquina virtual de um serviço de computação, ou unidade de execução indicada pelo serviço. Em EC2, ela pode estar executando, parada ou em outro estado; não deixa de ser instância ao parar.


S3 × EBS × EFS: objeto via API × disco de uma instância × arquivos compartilhados.

## 4. Operação, segurança e custo

Ter o recurso disponível é diferente de operá-lo corretamente. Aqui, observe o que continua sendo administrado pelo cliente, o que gera cobrança e como conservar ou recuperar dados.

### Cobrança

**Antes de ler este trecho:**

- **IA:** Inteligência artificial: conjunto de técnicas para tarefas como reconhecimento, previsão e geração de conteúdo. Cada serviço atende funções específicas, não qualquer problema.


**Armazenamento** (GB-mês, por classe) + **requisições** (PUT, GET…) + **recuperação** (IA/Glacier) + **transferência de saída** + recursos opcionais (replicação, Transfer Acceleration, monitoramento do Intelligent-Tiering, Inventory, Storage Lens avançado).


Entrada de dados é **grátis**; saída do S3 para o CloudFront é grátis.

### Segurança e responsabilidade compartilhada

**AWS:** infraestrutura, durabilidade e disponibilidade do armazenamento.

**Antes de ler este trecho:**

- **Macie:** Macie ajuda a descobrir e classificar dados sensíveis em objetos S3 compatíveis e a analisar aspectos de segurança dos buckets.
- **PII:** Informação que pode identificar uma pessoa. Sua identificação ajuda a planejar proteção de dados, mas não substitui avaliação do contexto e das regras aplicáveis.
- **criptografia:** Transformação usada para proteger a leitura dos dados. A chave e as permissões de uso precisam ser administradas; isso não impede toda exclusão ou erro do programa.


**Cliente:** **quem acessa** (políticas, Block Public Access), **criptografia** escolhida, versionamento, classificação dos dados (use **Macie** para PII).

### 🔄 Atualizações 2025-2026

Objeto de até **50 TB** (02/12/2025, confirmado em fonte oficial; não vale no GovCloud). Se só houver 5 TB nas alternativas, marque 5 TB.


🔄 **S3 Object Lambda** está fechado a novos clientes desde 07/11/2025.

## 5. Caso resolvido: ligando as peças

**Antes de ler este trecho:**

- **servidor:** Computador que atende pedidos de outros computadores. Um servidor web, por exemplo, responde aos pedidos enviados pelo navegador.
- **sistema operacional:** Software básico da máquina, como Linux ou Windows. Ele administra arquivos, memória e execução de programas; atualizar esse software é diferente de atualizar a aplicação.
- **autorização:** Decisão sobre o que uma identidade pode fazer em um recurso. Essa decisão depende das regras e do contexto da solicitação.
- **PDF:** Formato de documento. Um serviço de extração analisa conteúdo compatível; guardar um PDF num bucket não executa automaticamente essa análise.


A escola quer disponibilizar apostilas em PDF sem manter cada documento num disco específico de seu servidor. O trabalho principal é conservar e obter arquivos, não executar o sistema de matrícula.

Ela cria um bucket e envia um PDF como objeto, com uma chave como materiais/aula-1.pdf. A chave identifica o conteúdo; o nome não cria uma pasta de sistema operacional. O aplicativo solicita o objeto com autorização adequada. Não é preciso liberar o bucket inteiro ao público para que um fluxo autorizado obtenha o arquivo.

Se uma apostila precisar de conservação ou recuperação de versões, essas funções devem ser configuradas. Classe de armazenamento é uma escolha adicional sobre acesso e custo. EBS forneceria um disco para uma máquina; EFS forneceria arquivos compartilhados. São interfaces diferentes, e o programa precisa saber usar a escolhida.

**Recursos envolvidos:** Bucket de uso geral, objetos, chaves, versões, policies e lifecycle.

**Decisões que precisam ser tomadas:** Região, acesso, criptografia, versionamento e classes.

**Antes de ler este trecho:**

- **back-end:** Parte que processa regras e dados de uma aplicação. É diferente da interface que a pessoa vê no navegador ou aplicativo.


**Outra situação comentada:** PDF privado por tempo limitado: URL pré-assinada; ela não torna todo o bucket público.

**Por que não concluir mais do que isso:** Não executa back-end; limite de upload varia por método: PUT simples 5 GB, console 160 GB, multipart até 50 TB

### Confira se você compreendeu

**1. Qual dificuldade está sendo resolvida?**

Uma aplicação precisa guardar fotos, documentos e outros arquivos sem administrar o disco de uma máquina específica.

**2. O que a solução fornece?**

O S3 guarda dados como objetos: conteúdo, nome de identificação e informações associadas. Você organiza esses objetos em buckets e controla quem pode enviar ou ler cada um.

**3. Que conclusão seria incorreta?**
