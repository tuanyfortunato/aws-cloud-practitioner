# 3.3 Amazon EC2

## 🧠 Antes de começar

**Qual é a dificuldade?** Você quer colocar um programa em funcionamento sem depender do seu computador pessoal, mas precisa escolher o sistema e administrar o que será instalado.

**A ideia em palavras simples:** EC2 permite criar computadores virtuais na AWS. Cada máquina é uma instância; você escolhe sua capacidade, instala a aplicação e controla o acesso.

**Exemplo do dia a dia:** A escola instala seu sistema de matrícula numa instância. Os alunos usam o sistema pela rede; a equipe administra o servidor e atualiza seu software.

**O que não concluir?** EC2 fornece a máquina, não um sistema de matrícula pronto. Publicação, segurança, dados e custos associados continuam exigindo configuração e acompanhamento.

**📚 Palavras que aparecem aqui:**

| Termo | Em palavras simples |
|---|---|
| **Instância** | um servidor virtual em execução. |
| **AMI** | imagem pronta (sistema + software) usada para criar a instância. |
| **Graviton** | processador ARM da AWS, mais barato e econômico em energia. |

**Ao terminar este tópico, você deve saber:**

- [ ] Explicar **AMI**, **user data** e **key pair**.
- [ ] Escolher a **família** pelo uso (ML → computação acelerada; banco em memória → otimizada para memória).
- [ ] Diferenciar **EBS** (persistente) de **instance store** (temporário).
- [ ] Diferenciar **parar**, **encerrar** e **hibernar**.

<details>
<summary>Uma analogia para revisar a ideia</summary>

é como **alugar um computador**: a **AMI** é o "molde" com o sistema já instalado; a **família de instância** é o modelo do computador (para jogos, para planilhas pesadas, para muita memória); o **EBS** é o HD que fica guardado mesmo com o computador desligado.

</details>

> 🎯 **Como não errar na prova:** Leia o **uso** descrito: "treinar ML/GPU" → computação acelerada; "muita memória" → otimizada para memória; "dado temporário que pode ser perdido" → **instance store**; "acesso sem SSH" → **Session Manager**.

## 📖 Conteúdo

- **Servidores virtuais** com controle total do SO (IaaS). Cobrança por segundo (Linux) ou por hora, conforme o modelo de compra (ver [Domínio 4](../04-cobranca-precos-e-suporte/README.md)).
- **AMI (Amazon Machine Image):** modelo com SO e software para lançar instâncias. Pode ser da AWS, do Marketplace, da comunidade ou sua (personalizada).
- **Famílias de instância:**

| Família | Uso | Exemplos de letra |
| --- | --- | --- |
| Uso geral | Equilíbrio de CPU, memória e rede; servidores web, repositórios de código | T (burstable, acumula créditos de CPU), M |
| Otimizada para computação | Muito processamento: batch, servidores de jogos, HPC, codificação de mídia | C |
| Otimizada para memória | Grandes volumes de dados em memória: bancos em memória, análise em tempo real | R, X |
| Computação acelerada | GPU ou chips dedicados: machine learning, gráficos, cálculos científicos | P, G, Inf, Trn |
| Otimizada para armazenamento | Muita leitura e escrita em disco local: data warehouses, bancos NoSQL | I, D |

- **Graviton:** processadores ARM da AWS, com melhor relação preço/desempenho e menor consumo de energia (ligado ao pilar de Sustentabilidade).
- **User data:** script executado na primeira inicialização (instalar pacotes, configurar a aplicação).
- **Key pair:** par de chaves para acesso SSH. Alternativa sem abrir porta 22: Systems Manager Session Manager.
- **Armazenamento:** volume EBS (persistente, pode ser destacado) ou **instance store** (disco físico local, rápido, **temporário**: perde os dados ao parar ou encerrar a instância).
- **Elastic IP:** IPv4 público fixo que pode ser movido entre instâncias. Todo IPv4 público é cobrado.
- **Estados:** parar (stop) mantém o volume EBS e para a cobrança de computação; encerrar (terminate) apaga a instância. **Hibernar** salva a memória RAM no EBS.
- **Cai na prova:** "instância para treinar modelo de ML" = computação acelerada; "banco em memória" = otimizada para memória; "dados temporários de cache que podem ser perdidos" = instance store.

## ❓ Perguntas típicas

> Também estão nos [flashcards](../../flashcards/dominio-3.md).

- "Qual família de instância para aplicação com uso intenso de CPU?" → Otimizada para computação (C).
- "Para banco de dados em memória?" → Otimizada para memória (R, X).
- "Para machine learning com GPU?" → Computação acelerada (P, G).
- "Para servidor web com carga equilibrada?" → Uso geral (T, M).
- "Como instalar pacotes automaticamente ao lançar a instância?" → User data.
- "O que acontece com o instance store ao parar a instância?" → Os dados são perdidos.
- "Como manter um IP público fixo ao trocar de instância?" → Elastic IP.
- "Qual processador oferece melhor preço/desempenho e eficiência energética?" → AWS Graviton.
- "O que é uma AMI?" → Modelo com SO e software usado para lançar instâncias.

## 🔬 Aprofundamento para a prova — sem abrir o console

**Como funciona:** AMI define a base do sistema; tipo define CPU e memória; subnet define localização; EBS guarda dados; SG controla tráfego; role autoriza chamadas AWS da aplicação.

**Como escolher:** Escolha a família pelo gargalo: CPU, memória, armazenamento ou aceleração. Controle de SO aponta para EC2; menor gestão de infraestrutura pode apontar para alternativas gerenciadas.

**O que não concluir:** Instância ligada e ociosa continua cobrada. Parar uma EC2 com EBS não elimina cobranças de volumes, snapshots e outros recursos. Encerrar não equivale a parar.

### Exercício de decisão

Você terminou um estudo e parou a EC2. A fatura necessariamente fica zerada?

<details>
<summary>Resposta e por que as alternativas confundem</summary>

Não. A computação para na condição aplicável, mas os volumes EBS e recursos mantidos ainda podem custar. Compromissos de compra também permanecem.

</details>

**Verifique seu entendimento:** explique a escolha em voz alta e cite uma condição que mudaria a resposta. Nomear um serviço sem explicar o motivo ainda não demonstra domínio.

## 🔄 Atualizações 2025-2026 e detalhes extras

> Fonte: [pesquisa de atualizações](../../fontes/pesquisa-atualizacoes-2025-2026.md). Legenda: 📌 decorar · 🔄 mudou recentemente · ⚠️ pegadinha · 🧊 não precisa decorar.

- **Cobrança por segundo** com **mínimo de 60 segundos** (📌), na maioria das AMIs Linux e Windows, em todas as opções de compra (On-Demand, Spot, Savings Plans…).
- **Dedicated Host** = servidor físico inteiro para você, útil para **licenças vinculadas ao servidor** (BYOL por socket/núcleo). Pode ser comprado On-Demand ou via Savings Plans/reserva. **Dedicated Instance** = hardware dedicado sem visibilidade/controle de sockets.
- **Capacity Reservations:** garantem capacidade numa AZ **sem desconto por si só**, mas combinam com Savings Plans ou RIs regionais.
- 🧊 Não decorar: preço por hora, rede por tamanho de instância, número de ENIs.
